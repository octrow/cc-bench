# ADR-0005: Активное время как единственная временная метрика; отчёт даёт советы

Дата: 2026-07-30. Статус: принято (Daniil, гриль-сессия).

## Контекст
m2 показал: wall clock лжёт. "sdd медленнее на 45%" оказалось
25 минутами ожидания юзера. Пересчёт по транскриптам (span минус
паузы "конец ответа -> следующий ввод") перевернул вывод.

## Решения
1. **Время в отчётах = активное время.** Инструмент считает его
   автоматически из транскриптов (алгоритм /home/octrow/cybernet/sdd-kit/docs/archive/benchmark-m1-m2/comparison-runs.md).
   Wall clock - справочная колонка, никогда не в вердикте.
2. **Анализ использования тулзы обязателен.** Не только "сколько
   стоило", но и КАК арма работала: разбивка tool calls, что из
   артефактов тулзы реально читалось/вызывалось, где агент буксовал
   (повторные чтения, тупиковые ветви, компактификации).
3. **Итоговый отчёт обязан содержать раздел "советы по улучшению
   измеряемой тулзы"** (для sdd-kit - в первую очередь): что из
   тулзы не сработало/не активировалось, что жгло токены без пользы,
   что добавить/убрать. Отчёт без рекомендаций считается неполным.

## Последствия
- Экстрактор метрик парсит транскрипты всегда (не только OTEL).
- Формат отчёта: таблица median+IQR -> tool-usage разбор -> вердикт
  ДО/ПОСЛЕ -> рекомендации по тулзе.
