# ADR-0004: Стек и доменная модель инструмента

Дата: 2026-07-30. Статус: принято (гриль-сессия, Daniil).

## Решения
1. **Стек: Python + uv.** Один CLI-пакет (`uv run bench ...`).
   Bash - только внутри subprocess (git, claude, docker).
2. **Арма = YAML-спек.** `arms/<tool>.yaml`: install-шаги
   (cfg | repo-artifacts | path-binary | mcp), fired_check,
   primary_metric, hint-строка для CLAUDE.md (если нужна).
   В репо инструмента едет каталог готовых арм (наши 11).
   Новая тулза = новый yaml без правки кода.
3. **Пробы: шаблоны + LLM + заморозка человеком.** В репо - 5
   шаблонов (nav/bash/gh/web/long). Кондуктор-LLM инстанцирует их
   под целевой репо и пишет answer key; человек проверяет ключ и
   замораживает ДО прогонов. Полный автоген отклонён: кривой ключ
   тихо портит замер.
4. **Судья Tier F: LLM + выборочный человек.** LLM (opus/fable)
   судит все диффы вслепую, каждый с per-arm-правильным baseline
   (урок m1). Daniil перепроверяет случайную треть - дрейф судьи
   становится виден.

## Отклонено
- Bash-первый стек (логика арм/отчётов в bash - болото).
- Армы в коде (каждая тулза = правка инструмента).
- Судья только человек (автор = судья, биас m1) или только LLM
  (ошибку судьи никто не ловит).
